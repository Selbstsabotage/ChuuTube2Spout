# SHA-256 of every artifact setup.ps1 downloads.
#
# WHY THIS FILE EXISTS
# Three of the things setup.ps1 fetches are executed - 7zr.exe, Node.js and
# bgutil-pot.exe - and one is a native DLL loaded into the app's own process.
# Without a recorded hash, "what the maintainer tested" and "whatever the
# supplier is serving the moment you run setup" are the same thing, and there is
# no way for you to tell them apart.
#
# setup.ps1 verifies a downloaded file if it is listed here and REFUSES to use
# it on a mismatch. Anything not listed downloads with a loud warning.
#
# THE PIN HAS TWO HALVES
# The version lives in $PINNED at the top of setup.ps1; the hash lives here.
# They describe the same artifact and change together. Until 0.9.8 only this
# half existed - the URLs said "latest" while the hashes stood still - so every
# upstream release turned a working setup into a hard refusal. A refusal is
# what tampering is supposed to look like, which makes it the last thing you
# want happening routinely.
#
# TO UPDATE ONE ARTIFACT
#   1. bump its version in $PINNED in setup.ps1
#   2. delete its line below
#   3. powershell -ExecutionPolicy Bypass -File setup.ps1 -Portable -Pin
#   4. run the app and play something - -Pin records what downloaded, not what
#      works
#   5. cross-check the recorded hash against the SHA-256 the publisher shows
#      (GitHub on the release asset; for Node.js, SHASUMS256.txt), then
#      commit setup.ps1 and this file together
#
# Step 5 is the one that matters. Without it a pin only certifies that nothing
# changed since you last downloaded it, which is not the same as saying what
# you downloaded was genuine. Everything here comes from a GitHub release,
# where GitHub publishes each asset's digest, except Node.js, which publishes
# SHASUMS256.txt beside each release on nodejs.org:
#   mpv     https://github.com/shinchiro/mpv-winbuild-cmake/releases
#           (keeps only its latest 30 builds - a pinned one is deleted after
#           a few weeks, and setup then falls back to the newest build,
#           verified against the digest GitHub publishes for it)
#   Node.js https://nodejs.org/dist/  (SHASUMS256.txt in each version's folder)
#   7-Zip   https://github.com/ip7z/7zip/releases
#   bgutil  https://github.com/jim60105/bgutil-ytdlp-pot-provider-rs/releases
# 7-zip.org publishes no checksums at all, anywhere, which is why 7zr.exe is
# fetched from the ip7z release rather than from 7-zip.org/a/7zr.exe.
#
# <sha256>  <filename>
